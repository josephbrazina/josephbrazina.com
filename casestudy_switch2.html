Overview

The Problem

The Switch 2 HOME Menu is the hub players return to between games, and it has to stay legible and predictable whether the console is held in the hands, propped on a table, or docked to a TV. Our three-person team evaluated it with two methods: task-based usability testing, then prototyping. The usability test surfaced pain points, and I turned those findings into a redesign. I designed a wireframe and low- and high-fidelity interactive prototypes in Figma, and justified each design decision with human factors engineering (HFE) principles.

My role: I designed the wireframe and both interactive prototypes from start to finish. I also wrote the prototyping, HFE principles, prototyping findings, and redesign suggestions sections of the team report. My teammates, Arsalan Ashraf and Jyotshna Bali, led the design description and the usability testing.

From Pain Points to Prototypes

Designing From Test Results

The team's usability test had two participants, a novice and an expert. Each completed five tasks in handheld mode while thinking aloud, then filled out the System Usability Scale (SUS). Both scored 75, but their feedback differed. The novice struggled to tell what the unlabeled icons did, while the expert wanted faster access to common controls and more personalization. I used these findings as the starting point for every prototype decision.

What the usability test foundHow I addressed it in the prototypes
The expert wanted game icons that look more like the artwork on physical game cases, and larger icons.Full portrait cover-art game cards replace the small square icons.
The expert found the game title shown above each icon redundant.The cover art carries the title, so the cards have no separate title label.
The expert suggested a brightness control on the home screen, next to Wi-Fi, battery, and time.A brightness slider is grouped with the status indicators in the top-right corner.
The novice couldn't tell what several unlabeled icons did, and the expert asked for larger bottom icons.A wider, full-width navigation bar on the bottom edge, with larger buttons closer to the thumbs. The lo-fi prototype labels each button.
The expert wanted to customize the home screen theme around favorite games.Four Nintendo-themed home screens (Mario, Zelda, Kirby, Donkey Kong) alongside Light and Dark.

Note. Both participants were team members, so these findings are preliminary rather than generalizable.

Wireframe

The Blueprint

I started with a static, grayscale wireframe to lay out the redesign before adding interactivity. I built it on a 1920 × 1080 frame in Inter. Portrait rectangles with X's hold the place of game covers in a horizontal row. A black frame marks the selected game, and progress bars sit beneath each cover, left off for games without a story mode.

Ten circular placeholders along the bottom edge form the new navigation bar. Three in the top left hold profile icons. The top right holds a clock, Wi-Fi and battery placeholders, and a new brightness slider. I also designed the theme selector pop-up: a 3 × 2 grid of crossed-box previews, a Ⓑ Back button, and a black frame with a ✓ around the current theme. Arrows connect the screens to show the user flow, and eight annotations explain the changes.

Low-Fidelity Prototype

Making the Flow Clickable

Next, I turned the wireframe into an interactive lo-fi prototype. I duplicated the light home screen and its theme selector, then gave the copy a red background to represent the Mario theme. Each placeholder got a game title (Donkey Kong Bananza, Mario Kart World, Tears of the Kingdom, and more), and each theme preview got a theme name. Each nav button got a text label.

In Figma, I wired the screens together. The game row scrolls horizontally. The Themes button opens the theme selector, choosing Light or Mario switches the home screen, and pressing Ⓑ Back or clicking outside the pop-up returns to the current home screen.

High-Fidelity Prototype

From Gray Boxes to Real Screens

I built the hi-fi prototype on top of the lo-fi layout. I edited every game cover to remove console branding and age ratings, so only the cover art remained. I added an "All Software" card with a 3 × 3 grid icon to the end of the game row. The nav icons came from the open-source Iconify plugin and are colored individually. The profile icons are actual Switch 2 profile icons.

For focus and contrast, I used a single cyan accent for the progress bars, the brightness slider, and the glowing selection frame around the current game. Covers, progress bars, and status items also got subtle drop shadows and glows so they separate cleanly from any background.

Tuning Each Theme

All six home screens share one layout. Only colors and the background change, so every theme needed its own contrast adjustments.

Human Factors Engineering

Why Each Design Choice Works

I grounded every addition and change in an established HFE principle, so each design decision rests on evidence rather than intuition alone.

Design choiceHFE principlesHow it helps the user
Full cover-art game cardsFitts' law; attentional salience & visual hierarchy; recognition over recallLarger targets are faster to select, especially by touch in handheld mode. Familiar box art lets players spot a game instead of reading for it.
Wider bottom nav barFitts' law; thumb reach on handheld touchscreens; visual hierarchyBigger buttons sit closer to the thumbs, and the layout separates secondary system functions from the primary game row.
Home-screen brightness sliderMinimizing information access cost; functional grouping; compatible mappingA frequent adjustment no longer requires System Settings. It sits with the other status indicators, and sliding left dims while sliding right brightens, matching expectations.
Story progress barsKnowledge in the world; proximity compatibility principle; redundancy gainProgress is visible without opening the game. The bar sits directly beneath its game, and a percentage backs up the bar.
Cyan selection frame, glows & shadowsAttentional salience; discriminability; figure-ground segregationThe cursor is easy to find, and covers separate cleanly from any background.
Nintendo-themed home screensPersonalization; aesthetic-usability effect; consistency & mental modelsPlayers can personalize their console. Because the layout never changes between themes, spatial memory of where everything sits carries over.
Nav icon colors per themeFigure-ground segregation; luminance contrastButtons stay distinguishable from the background art.
Image previews in the theme selectorRecognition over recallPlayers see each theme instead of having to remember what a name looks like.
Cyan frame + ✓ on the current themeRedundancy gain; discriminabilityTwo cues mark the selection. Tailored shadows, glows, and borders keep preview edges visible on every background.
Ⓑ Back or tap outside to closeUser control and freedomTwo quick ways to return to the home screen.
"All Software" tile with grid iconSignifiers; redundancy gain; visibility of system statusThe grid signals the full library, and its spot at the end of the row shows the row is finite.

Note. Principles drawn from Fitts (1954), MacKenzie (1992), Bergstrom-Lehtovirta and Oulasvirta (2014), Wickens et al. (2022), Wickens and Carswell (1995), Nielsen (1994), Norman (2013), Sanders and McCormick (1993), Blom and Monk (2003), Kurosu and Kashimura (1995), Tractinsky et al. (2000), and Wagemans et al. (2012).

Expected benefit

Faster game selection, easier thumb reach, fewer trips into System Settings, and a home screen players can make their own.

Trade-off to watch

Busy themed backgrounds such as Mario and Donkey Kong may add cognitive load and compete with the game cards for attention (Sweller, 1988). Nav buttons tinted to match a theme may also lose salience.

What I Learned

Prototyping Findings

Prototyping showed me how well-designed the original HOME Menu already is. It's minimalist and puts the user first, presenting only a few essential tasks with almost no visual clutter. That made it hard to find pain points worth redesigning. Building interactive prototypes instead of static mockups helped me understand how each redesigned element would actually behave before implementation, and taught me Figma's prototyping tools in depth.

What the Original Gets Right

Clear cursor location

A cyan frame always shows which element is selected.

Button prompts

Small cues like "Ⓧ Close software" and "Ⓐ Continue" in the bottom right remind players which button does what.

Games come first

Game cards are the most salient element and sit in the user's focal vision, with system areas one tilt or press away.

Status at a glance

Wi-Fi and battery level are always visible in the top-right corner.

Redesign Suggestions

Strengths, Counterarguments & Next Steps

The prototypes bring four improvements suggested by usability testing: larger game cards, a redesigned and larger navigation bar, a home-screen brightness slider, and Nintendo-themed home screens. Each comes with a counterargument worth weighing against Nintendo's minimalist design language.

RedesignCounterargumentPossible fix
Nintendo-themed home screensBusy backgrounds add visual clutter and cognitive load.Use simpler backgrounds, which would also sharpen the edges of game cards and nav buttons and keep the game row the clear focal point.
Theme-matched nav buttonsButtons colored like the background lose salience.Use nav button colors that contrast with each background.
Home-screen brightness sliderUnnecessary clutter for players who use auto-brightness.Add a setting to show or hide the slider.
Theme selector pop-upOnly six themes fit at once.Use a larger pop-up if more themes are added.

Next step: run a usability test on the hi-fi prototype to confirm whether each HFE principle actually improves the experience, and find which changes to keep, adjust, or remove.
